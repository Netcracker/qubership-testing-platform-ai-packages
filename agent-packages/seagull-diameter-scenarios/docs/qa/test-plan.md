# Test plan

The plan covers the five tasks of the package in both ways, as plain requests and as commands, and the settings. Read
the [guide](README.md#run-a-case) first for how to run a case and what the verdicts mean.

## Inputs

Make a work folder and copy the [sample data](README.md#sample-data) into it:

| Name in the prompts         | What it is                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------ |
| `work/dictionaries`         | The folder `tests/fixtures/dictionaries`: `Gy.xml` and `DiameterBaseProtocol.xml`                      |
| `work/dictionaries-no-base` | A copy of that folder with `DiameterBaseProtocol.xml` removed                                          |
| `work/steps-export.csv`     | The file `docs/qa/data/steps-export.csv`                                                               |
| `work/steps`                | The folder `tests/fixtures/steps`: three steps in two sessions                                         |
| `DICT`                      | The `diameter-dictionary.xml` that case A1 writes. Phases C to E use it                                |
| `OCS`                       | `127.0.0.1:66666`, a local address with a port number that is out of range, so no OCS can answer there |

The prompts below say what to type. Where a case writes a folder without a name in the prompt, the agent picks the first
free default name next to the input and reports it; use that name in the later cases.

## Step 0: the environment

1. Install the package from the branch under test. List the skills the project now has: expect the six commands, the
   six plain skills, and `seagull-diameter-common`.
2. Read the `description` of each. The plain skills have no `disable-model-invocation`, and the commands have it.
3. Run `/seagull-diameter-settings`. Expect the runner, the path of `seagull.exe` or the image, and the dictionary
   path with the file each came from. The runner is set to the Seagull you will use; the dictionary path is not set yet.
   Keep a copy of `.seagull-diameter/config.json`.

Restore `.seagull-diameter/config.json` from your copy after this phase.

## Order

```text
Step 0
  -> A1 ... A7       (A1 gives DICT)
  -> B1 ... B7       (B1 gives the steps)
  -> C1 ... C13      (C2 needs DICT and work/steps)
  -> D1 ... D5, E1 ... E6   (need the scenarios of C2 or C8)
  -> F1 ... F8, S1, S2
```

The cases A, B, F5, F6, F7, and S do not depend on each other. If an input is missing, mark the later cases that need it
as blocked and go on with the rest.
